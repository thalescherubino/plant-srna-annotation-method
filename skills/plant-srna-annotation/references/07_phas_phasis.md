# Step 7: Find *PHAS* loci with Phasis

[Back to the skill map](../SKILL.md) · Previous: [06_mirna_validation_mirscore.md](06_mirna_validation_mirscore.md) · Next: [08_structural_rna.md](08_structural_rna.md)

## Goal

21-nt and 24-nt *PHAS* loci, each with the libraries that support it and the phasiRNAs Phasis assigns to its phased units, plus the separate, weaker *PHAS*-like class.

Phasis alone does the phasing analysis (ShortStack 4 has none). Published *PHAS* catalogs are not used as references; only loci called in the study are annotated.

Phasis documents its own commands, outputs and scores in its README (sections "Understand the Outputs", "Use Your Own Data", "Manage Runs and Outputs") and in its `docs/` folder (`scoring.md`, `phasirna_output.md`, `advanced_usage.md`). Where this page and those documents seem to disagree, the Phasis documents win; report the difference.

## The four runs and the comparison

Run **all** Phasis analyses of a species in **one run directory**, **one after another**, each with its own `--outdir`:

```bash
cd runs/phas/phasis        # contains genome/<genome>.fa (+ .fai) as links
phasis -libs tag/*.tag -libformat T -reference genome/<genome>.fa --reference_id_mode preserve \
  -phase 21 -cores 32 --outdir 21_results_individual
phasis ... -phase 24 --outdir 24_results_individual
phasis ... -phase 21 --pool_libraries --outdir 21_results_pooled
phasis ... -phase 24 --pool_libraries --outdir 24_results_pooled
# final set per phase: the union of both runs (see "Combining the runs" below)
phasis-compare 21_results_pooled 21_results_individual --label-a pooled --label-b individual --outdir 21_results_combined
phasis-compare 24_results_pooled 24_results_individual --label-a pooled --label-b individual --outdir 24_results_combined
```

- **Why one directory:** the run directory (where you start `phasis`) holds the intermediates, `index/`, `processed_libraries/` and the `phasis.mem` cache. Phasis checks this cache to decide which steps it can reuse, so 21- and 24-nt runs in the same directory share the index and processed libraries. `--outdir` only changes where the final results go (Phasis README, "Manage Runs and Outputs"). The index is expensive to build (25 min for tomato, mostly compression).
- **One run at a time:** the Phasis README ("Run a Real Example") says to run only one analysis at a time per working directory; different `--outdir` values do not make simultaneous runs safe. A run that must go in parallel needs its own directory, and repeats the index cost.
- **New genome or new library set = new run directory.** The README advises separate run directories for separate experiments.
- **Clean up only with Phasis's own commands** (`phasis -cleanup`, or `-cleanup_all`, which also removes the index and `phasis.mem`), started from the run directory, after all runs and comparisons are done and the project lead agrees. Cleaned intermediates must be regenerated by any later run (Phasis `docs/advanced_usage.md`, section "Cleanup").
- **Exact matching:** keep `-mismat 0` (the default) and record `-maxhits` (default 25: Phasis keeps reads with fewer than 25 reported placements).
- **Score cut-off:** `-phasisScoreCutoff` defaults to 50 for 21 nt. For phases above 21 Phasis clamps it to 250-300 and prints an `[INFO]` line when it does. This project keeps the defaults; record the value Phasis reports in the log.
- `--reference_id_mode preserve` keeps the genome's own sequence names in Phasis's indexed reference and its outputs. Without it, a genome run uses compact numeric IDs.
- **Individual vs pooled:** Phasis analyses each library individually by default. `--pool_libraries` combines all libraries into one virtual library (its `alib` is `ALL_LIBS`) before candidate detection. Pooled runs write tables, GFF and locus plots, but no cross-library heatmaps. The README warns that neither mode is guaranteed to recover every locus found by the other, which is why we run both.
- **Our experience with the two modes:** we treat per-library calls as replicate-like evidence. Pooled runs find weak loci, but for 24 nt they also pick up dense hc-siRNA clusters with only short phased stretches. Rice pooled 24 nt added 3,756 loci (median 19 kb; the combined set spans about a quarter of the genome).
- **Do not filter pooled 24-nt calls before looking.** First show the strict and exact-support Howell score distributions for pooled-only loci versus loci also found per library, and let the project lead choose the cut-off. In rice, strict Howell separated the two groups well (AUC 0.90). This is a project filter applied after Phasis. Phasis's own `-min_Howell_score` (default 12.5) applies to the main `Peak_Howell_score`, and the Phasis scoring guide says the strict score is not simply a replacement threshold for the main score.

## Combining the runs (`phasis-compare`)

From the Phasis advanced guide (`docs/advanced_usage.md`, section "Combine Completed Runs"):

- Only loci whose final class is *PHAS* are combined; *PHAS*-like loci are not.
- Loci are matched when they overlap directly on the same chromosome (default `--overlap-buffer 0`).
- The default `--prefer auto` detects a pooled input (from `alib = ALL_LIBS`) and keeps the **non-pooled** (individual) record for a shared locus. Finer individual loci that overlap one broad pooled call are all kept. A pooled locus that overlaps no individual locus is added as a pooled-only locus. Override with `--prefer a` or `--prefer b`.
- The output has the usual Phasis tables (`<P>_calls.tsv`, `<P>_all_clusters.tsv`, `<P>_classification_evidence.tsv`, `<P>_phasiRNAs.tsv`, `<P>_PHAS.gff`) for the deduplicated union, plus audit tables of shared and run-specific loci, `comparison_summary.txt` and `comparison_manifest.json`. No plots.
- A non-empty `--outdir` is refused unless `--force` is given.

## Run time and where it goes

| Run | Tomato (800 Mb, 100 libraries) |
|---|---|
| 21 nt individual, from scratch | 4.3 h at 32 cores |
| 24 nt individual | more than 28 h at 64 cores |
| 24 nt pooled (rice, 374 Mb) | 28.5 h |

Measured slow stages in the 21-nt run: cluster scoring (84 of 257 min), feature assembly (43 min), compressing processed libraries (21 min), plots (21 min), reference compression (20 min), parsing alignments (16 min). The 24-nt run is far slower because about 100× more clusters pass the pre-filter:
- cluster scoring computes statistical tests (a hypergeometric and a rank-sum test, combined per window) at every occupied position, library by library (code: `phasis/stages/cluster_scoring.py`);
- feature assembly then ran for more than 10 hours.

These are tool-level issues: report them to the Phasis developers, do not patch the tool inside an annotation run. Plan the queue so other steps run meanwhile ([04_compute_and_queue.md](04_compute_and_queue.md)).

## Outputs (per `--outdir`)

File names follow the Phasis README, section "Understand the Outputs"; `<P>` is the phase (21 or 24).

| File | What it is |
|---|---|
| `<P>_calls.tsv` | the main table of high-confidence *PHAS* calls. One row per locus **per supporting library** (`alib`): coordinates, Phasis score, Howell scores. Count distinct `identifier` values for loci |
| `<P>_classification_evidence.tsv` | evidence for the *PHAS*, *PHAS*-like or non-*PHAS* interpretation of every classified cluster in every library: `final_class` and `evidence_reason` |
| `<P>_all_clusters.tsv` | every evaluated cluster with its features, including candidates that did not pass final reporting |
| `<P>_PHAS.gff` | coordinates of the *PHAS* loci, one line per locus |
| `<P>_phasiRNAs.tsv` | individual phasiRNA sequences and abundances, assigned to the main or secondary phased units of each called locus |
| `<P>_PHAS_like/` | the *PHAS*-like class kept separately: its own calls, evidence, GFF, phasiRNAs and plots |
| `<P>_PHAS_locus_plots/` | one diagnostic plot per locus |
| `<P>_PHAS.pdf`, `<P>_Abundance_PHAS*.pdf`, `<P>_Howell_scores.pdf` | cross-library heatmaps of classification, abundance and Howell scores (individual runs only) |

How to read them, with tomato numbers: [09_outputs_and_interpretation.md](09_outputs_and_interpretation.md).

## Counting *PHAS* loci

Phasis can report more than one **phased unit** in one locus: a main unit (anchored on the highest phasing score position, HPSP) and secondary units, which can be overlapping alternative registers or spatially separate phased regions in the same locus (Phasis README, "Individual phasiRNAs and phased units"). Phasis calls these inferred structures, not proof of separate precursor transcripts.

- Report both GFF loci and phased units, and say which one you count.
- Count a unit by grouping `identifier`, `cID`, `alib`, `phase` and `window_unit_id` in `<P>_phasiRNAs.tsv`. Unit IDs such as `unit_main` are local to one locus and library, not global (Phasis `docs/phasirna_output.md`).
- Rice 21-*PHAS*: 1,011 GFF loci against 1,535-1,667 phased units (project count; write down the counting rule you used).

## Interpretation limits

- A genomic interval rich in 21- or 24-nt reads is not a *PHAS* locus by that fact alone.
- Reads inside a *PHAS* interval are not automatically phasiRNAs. Only phase-length reads that Phasis assigns to a phased unit are exported, and even these include reads 1 nt off the expected position (`core_offset`).
- The *PHAS* and *PHAS*-like labels are not experimental proof of how the sRNAs are made (Phasis README, "What are *PHAS* and *PHAS*-like loci?").
- Phasing evidence says nothing about mobility, targets or function.
